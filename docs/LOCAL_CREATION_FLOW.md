# 创作方案与本地项目流程

当前开发分支把像素桌面接入了 Electron 应用，并接通了 Codex 方案整理和独立语音识别接口。运行 `npm run dev` 可打开应用；已有依赖时无需重新安装。

## 使用流程

1. 在桌面输入想法，Enter 换行。点击「AI 整理方案」或 Cmd/Ctrl+Enter，请已连接的 Codex 整理方案；这一步会使用模型额度，但不生成游戏或素材。需要先在设置中登录，不要求图片服务就绪。
2. AI 返回游戏名称、玩法、画风、操作、胜负条件和第一版范围。方案标记为「AI 方案」，每项都可以修改；原始想法与参考说明由应用原样保留。
3. 未连接模型或只想手动填写时，点击「用本地模板」。模板明确标记来源，整个过程离线；AI 失败不会偷偷换成模板。
4. 点击「创建项目」，选择一个空文件夹，保存已确认方案和 Web 基础工程。返回「我的游戏」可重新打开。
5. 在工作台明确点击「开始生成」或发送制作要求后，才进入现有游戏制作链路。这一步另需配置运行时和素材服务。初始预览是基础模板，不能视作已经生成的游戏。

工作台会先检查项目目录、Codex 登录、制作模型、图片生成能力，以及 Godot 项目的引擎和 Web 导出模板。缺少条件时显示处理入口，修复后可重新检查。设置关闭或切换制作模型后自动刷新检查，开始制作时后端重新校验。条件就绪仅表示本地配置满足启动要求，真实额度和生成效果在实际服务调用时确认。

AI 整理只提交一轮请求，不自动修复重试。格式错误、服务失败、取消均保留输入。取消时等待模型 turn 的终止通知，取消请求收到回应不等于已经停止；若无法确认停止，会显示错误并提示检查运行时连接。刷新或关闭窗口也会向主进程请求取消；迟到结果不会覆盖草稿。

创建项目本身不调用模型、图片或音频接口，图标由本地程序绘制。取消选目录、创建失败都会保留方案；可重试原目录，或通过错误提示中的「换个文件夹」选择新位置，已产生的文件不会自动删除。

## 语音输入

1. 在「设置 → 语音识别」填写完整 HTTPS 转录地址、模型和 API Key。支持 MiniMax ASR 和 OpenAI 兼容服务。MiniMax 国内接口为 `https://api.minimax.cn/v1/speech_to_text`，国际接口为 `https://api.minimax.io/v1/speech_to_text`，模型均为 `asr-1.0`；Key 必须对应账户区域并拥有语音识别访问权限。此配置与生成配音/音乐的媒体 API 分开，Codex 登录不等于拥有语音 API 密钥。保存配置不会调用服务或验证额度。
2. 打开「语音输入」，点击「开始录音」后才请求系统麦克风权限。每段最多 3 分钟 / 8 MiB，停止录音不会自动上传。
3. 点击「转成文字」才在本机将录音转成单声道 16 kHz PCM WAV，然后发送至配置的服务并可能产生费用。转换失败不会上传，转录失败保留录音供手动重试；取消只停止本机等待，不能保证服务端未处理或未计费。
4. 在结果框检查并修改文字，再点击「填入想法」。文字追加到当时最新的想法末尾，不覆盖用户同时输入的内容，也不自动整理方案。合并超过想法框 1600 字上限时保留识别结果，等待用户编辑缩短。

关闭、最小化语音窗口或离开桌面时停止录音、释放麦克风并取消未完成的本机转录。原始音频和未确认结果只存在内存；确认填入的文字遵循想法草稿的本地保存规则。API 密钥通过 Electron safeStorage 加密，保存在应用 userData 下的 `speech-settings.json`，不会回显到页面；变更服务域名必须重新配置密钥。预览游戏的 iframe 无权通过这条链路取得麦克风权限。

接口依据：[MiniMax 国内语音识别 API](https://platform.minimax.cn/docs/api-reference/speech-to-text)、[MiniMax 国际语音识别指南](https://platform.minimax.io/docs/guides/speech-to-text)。请求使用 multipart 的 `file` 和 `model` 字段，读取 JSON `text`，不自动重试或跟随重定向。

### 本机 ENV 配置入口

本地源码运行时，可复制根目录 `.env.example` 为 `.env.local`，填写 `GU_SPEECH_API_KEY` 后重启应用。模板已填写 MiniMax 国内地址和 `asr-1.0`；国际账户需修改 endpoint。`.env.local` 已被 Git 忽略，不会打进安装包。

主进程只读取三个指定语音字段，不向 `process.env` 注入，不把 Key 传给 Codex 子进程或前端。没有已保存密钥时才导入到系统加密设置；已有密钥时，以应用内设置为准，不被 ENV 覆盖。成功导入后可以清空 ENV 中的 Key；如果要移除密钥，需同时清空 ENV 和应用设置，避免下次启动重新导入。打包后的应用通过「设置 → 语音识别」配置。

本机 Codex 使用应用独立的 `codex-home` 登录缓存；连接状态以应用读取账户和模型的结果为准。连接检查不会运行游戏生成或方案整理。

## 保存位置与代码入口

- 未确认的输入、方案、来源标记及桌面窗口位置保存在应用的 localStorage。
- 项目目录内 `.gu/creation-brief.json` 保存结构化方案与原始想法；目录记录的 `idea` 保存完整文本方案，供游戏 Agent 使用。
- `src/shared/creationBrief.ts`：规划输入、方案字段验证、本地模板与格式化。
- `src/main/creationBriefPlanner.ts`：单轮结构化规划、请求去重、取消与临时目录清理。
- `src/main/codexAppServer.ts`：线程局部配置、结构化输出与取消终态等待。
- `src/main/creationDraftService.ts`：本地项目创建和重试恢复。
- `src/shared/speech.ts`、`src/main/speechSettingsStore.ts`、`src/main/speechTranscriptionService.ts`：语音格式/大小边界、密钥配置与转录请求生命周期。
- `src/renderer/desktop/SpeechInput.tsx`、`src/renderer/components/SpeechSettings.tsx`：录音、识别结果确认和语音配置。
- `src/main/main.ts` / `preload.cts`：`gu:brief:plan`、`gu:brief:cancel` 与本地项目 IPC。
- `src/renderer/desktop/` 和 `App.tsx`：桌面、方案编辑与原有工作台的接线。

规划使用应用临时空目录、临时线程和只读沙箱，通过线程局部配置关闭命令执行、浏览器、图片生成、子 Agent 等能力及继承 MCP 服务，不修改全局配置。MCP 配置只用于主进程向同一 Codex 运行时设置禁用状态，不进入提示词或方案。原有游戏制作线程不受这些局部限制影响。

项目保存在本机，不包含云同步、账户计费或公开发布。

## 验证与当前限制

类型检查和 renderer/main 构建通过。局部测试覆盖规划输入、模型结果验证、原文保留、重复请求、取消与迟到结果、取消未确认、运行时参数传递和本地项目创建；没有运行完整生成测试套件。

语音新增 9 项聚焦测试通过，覆盖加密配置、域名绑定、输入/输出边界、请求去重、错误脱敏、超时与取消。独立 Electron 联调使用合成录音、模拟 HTTP 和模拟密钥编码器，实际走设置页、preload、IPC 与转录服务：确认配置保存不访问服务、不加载 Codex 扩展；录完不自动上传；仅主窗口音频可获权限；识别结果可编辑并追加最新想法；超过 1600 字保留双方文本；关闭后取消请求并丢弃迟到结果；迟到的麦克风流也会释放。Renderer 错误数为 0，真实麦克风、真实 API 与游戏生成调用数均为 0。mac 麦克风用途说明与签名 entitlement 已加入，plist 语法检查通过，未制作安装包或验证正式签名后的系统授权弹窗。

Electron 联调使用隔离临时资料目录、真实界面与 IPC/规划/项目服务，只将模型运行时替换成本地模拟。已检查：无效输出保留原文且不自动重试、取消等待与迟到结果丢弃、模板不请求模型、刷新取消后台规划、AI 成功只进入编辑页、确认后保存项目。最终 Renderer 错误数为 0，真实模型与游戏生成调用数均为 0。

上述记录对应早期隔离联调。后续本机已完成真实 Codex 方案整理和一次游戏制作链路；这不代表任意账户、网络或模型均已验证。平台检查与生成游戏质量应分开评估，发布仓库不提供共享账户或生成后端。

语音同样尚未进行真实服务验收：识别准确率、实际设备录音质量、网络延迟和账户额度需在用户配置语音服务后验证。默认模型与请求协议按上述官方文档核对；兼容服务仍需支持录音格式与 JSON `text` 返回约定。

保留原有 pack/scene ID 和动作契约，已有设置无需迁移；旧 `fishing` ID 现在对应天台休息站，并显示用户配置的编队。原工坊专用遮挡层停用。旧资源文件保留在源码中，但当前运行入口与构建不再引用旧工坊 GIF、旧角色 PNG 或旧图标。用户项目中的游戏图片、项目图标和实际预览内容不受影响。

本轮构建及 25 项相关既有检查通过。隔离 Electron 检查覆盖加载、页面转场、运行/等待/失败状态、设置预览、保存后的旧场景 ID 兼容与编队显示；Renderer 错误和旧配图资源请求均为 0。任务状态由本地模拟驱动，没有调用模型、素材服务或执行游戏生成。字体构建兼容保持有效。
